# Local vocabulary and media library

`scripts/crawl_babadum.py` collects public Ba Ba Dum game rounds and saves their
word metadata, SVG images, and original audio. It submits no answers or scores.
Python 3 and its standard library are sufficient on macOS/Linux.

## Run and resume

Run from the repository root. A small Spanish run downloads the recordings and
images for the words encountered in three rounds:

```sh
python3 scripts/crawl_babadum.py --languages es --rounds-per-language 3
```

Check every supported language without downloading audio:

```sh
python3 scripts/crawl_babadum.py --languages all --rounds-per-language 1 --metadata-only --round-robin
```

Extend the library with a bounded collection run:

```sh
python3 scripts/crawl_babadum.py --languages all --round-robin --rounds-per-language 5000 --target-per-language 10000 --max-no-new 500
```

The default output is `data/library/`. Repeating a command automatically resumes
that directory: existing records and media are reused, missing audio for known
records is downloaded first, and new records are merged. `--metadata-only` still
saves SVGs. Both Ogg and M4A are downloaded when available, so older iPhones can
use M4A. Missing alternates are backfilled on resume. A confirmed 404/410 is
recorded in `audio_unavailable` and does not count as an error or get requested
again; transient errors remain retryable. One process
may own an output directory at a time, enforced by `.crawler.lock`.

With one worker, the default request interval is one second across both API calls
and media downloads; `--interval` cannot be below 0.5 seconds. Parallel workers
instead share the aggregate `--request-rate` limit. Requests time out after
20 seconds and transient failures receive at most two retries with backoff.
`--min-free-mb 512` reserves disk space. The crawler stops with exit code 2 if
free space drops below this threshold. Ctrl+C or SIGTERM checkpoints and exits
with code 130, including when launched from a background shell.

## Languages and coverage

The 21 native game language codes are processed in this order, with Spanish first:

```text
es gb us pl de fr it ru jp se gr cz lt pt ro hu da cn eo tr uk
```

`--round-robin` collects one round per language per cycle, then rotates through
all 21 again. Spanish gets the first slot without delaying other languages until
its collection finishes. Each language retains its own cumulative round count,
no-new count, and target for the invocation; finished languages are skipped.
Known missing audio formats are backfilled once per language before its first
sampling slot. Omitting the flag retains sequential language collection.

`gb` and `us` are the British and American English recordings. Interface-only
languages are excluded. Arabic is generated by the app's existing translation
flow and has no native Ba Ba Dum recording library to crawl.

The API returns random rounds. Each round may contribute up to four records,
including its distractor choices; repeated records add no coverage. There is no
established API selector for an exact word, and 1500 is a collection target,
not proof that all words have been captured. The crawler stops each language
when it reaches its target, uses its round budget, or sees `--max-no-new`
consecutive rounds without a new concept. The target counts metadata records
for metadata-only runs and locally available recordings for media runs.
`--rounds-per-language` defaults to 100 and is capped at 5000 per invocation.
The longer examples use a deliberately high target of 10000 so a presumed
1500-word count does not stop collection; the round budget or no-new limit
instead bounds the run. Collection across all languages may take many hours;
reruns extend coverage.

Progress is one JSON object per line, with language, words, local audio count,
new records, and errors. `phase: "backfill"` identifies downloads of known
records. Each round and backfill attempt atomically checkpoints `vocabulary.json`.
Individual failures remain retryable on the next run. A normal exit means the
bounded run finished; inspect coverage and errors to assess its result.

## Files and application integration

```text
data/library/vocabulary.json
data/library/media/images/<concept-id>.svg
data/library/media/audio/<language>/<audio-file>.ogg
data/library/media/audio/<language>/<audio-file>.m4a
```

The version-1 manifest groups records by language and shared concept ID:

```json
{"version":1,"languages":{"es":{"id":4,"words":{"1253":{"id":"3141","word":"volar","audio_file":"volar_3141","image":"media/images/1253.svg","audio":"media/audio/es/volar_3141.ogg","audio_alt":"media/audio/es/volar_3141.m4a"}}}}}
```

`word_key` from the API becomes the concept key (`1253` above). The localized
record ID (`3141`) matches the audio suffix. `audio` is the primary file (Ogg
preferred); `audio_alt` is the second format when available. A single available
format counts toward audio coverage. `color_key`, when present, is retained.
SVG artwork is stored once per shared concept. Audio is downloaded only from the
exact server-provided filename; the crawler does not guess translated URLs.

The application's static server exposes the default library under
`/data/library/`. `library.js` loads its manifest and uses matching local audio
and images as they become available. With **Play translation: On**, the menu
language selects the translation and its recording. Missing library entries
fall back to verified recordings cached during normal play, then translated
text and browser speech as available. Arabic continues through the existing
translation/speech fallback. The library does not make the game fully offline:
new game rounds still come from Ba Ba Dum.

Reload the page to load newly collected manifest entries. A custom
`--output-dir` must be copied or served at `/data/library/` for the current
frontend to find it. Keep the manifest and its referenced media together.

## Local collection, Git, and deployment

The local repository is the source of truth. Vocabulary, SVGs, Ogg, and M4A files
under `data/library/` are tracked in Git. Runtime logs, PID files, locks, and
temporary checkpoints are ignored. The former server collector has been stopped;
do not run a separate server collector while deploying local snapshots.

Start a resumable background crawl from the repository root:

```sh
nohup python3 scripts/crawl_babadum.py --languages all --workers 21 --request-rate 8 --rounds-per-language 5000 --target-per-language 10000 --max-no-new 500 > data/library/crawl.log 2>&1 < /dev/null &
echo $! > data/library/crawl.pid
tail -n 5 data/library/crawl.log
```

The computer must stay awake and connected for the local crawl to progress.
Parallel collection uses at most one process per language (21 workers). All
workers share an aggregate request-start limit: the command above allows eight
requests per second across API calls and audio downloads together. The supported
maximum is eight requests per second. Private worker checkpoints in `.workers/`
are ignored by Git; the coordinator merges them into the versioned manifest.
HTTP 429 pauses all workers, honoring `Retry-After` or using increasing cooldowns.
Progress reports include request and rate-limit counters. With one worker,
`--round-robin` retains the sequential rotating mode.

An initial bounded probe of 30 API requests at 1/2/4/8 concurrency saw no HTTP429,
but one truncated response in the highest stage. A second probe using shared
pacing completed 32/32 requests at eight starts per second with no HTTP429 or
transport failures. Eight starts per second is the operating cap, not proof of
an absent or permanently higher rate limit.

Before committing a new snapshot, stop it and wait for its checkpoint:

```sh
kill -TERM "$(cat data/library/crawl.pid)"
```

Then stage the complete library together, commit, and push:

```sh
git add data/library
git commit -m "Extend local vocabulary and recordings"
git push origin main
```

Pushing to `main` runs GitHub Actions and deploys the committed snapshot. Both
the workflow and `deploy.sh` include the library. The workflow's rsync protection
rule preserves extra destination library files during `--delete`, while still
updating committed files, including the manifest. Logs, locks, and PID files
are excluded. An older commit can still replace the manifest with its older
snapshot; the protection prevents media deletion, not manifest rollback.

New local downloads reach GitHub and production only after another commit and
push. No automatic commits or pushes are performed. Re-run the background command
after a snapshot to continue collecting. Raw media increases repository size as
coverage grows; each sound remains a separate small file.

Static media updates need no app service restart. Validate crawler behavior with:

```sh
python3 -m unittest discover -s tests -p test_crawler.py -v
```

## SOCKS failover supervisor

`scripts/crawl_with_socks.py` runs the crawler through the SOCKS5 URL in the
private file named by `BABADUM_SOCKS_FILE`. It requires PySocks and resolves
upstream hostnames through the tunnel. Credentials must stay outside Git.

`scripts/watch_crawler.py --refresh-command /path/to/refresh --socks-file /path/to/private-url`
runs 21 workers at the existing aggregate eight requests/second cap. The refresh
executable must validate a route, write its SOCKS URL to the private URL file,
and exit successfully. After five minutes without new vocabulary records, the
supervisor stops and checkpoints the crawler, refreshes the route, and resumes.
It also resumes after the bounded crawler exits. Stop the supervisor with SIGTERM
to checkpoint its crawler. Runtime status is in `data/library/watch.log` and
`data/library/watch.pid` when launched using those paths.

The current machine uses `/tmp/babadum-proxy-rotate.py` and
`/tmp/babadum-proxy.url`, with two verified tunnels from the us1 proxy pool.
These private runtime files may need recreation after reboot or temporary-file
cleanup. A stall can also mean the random vocabulary has been exhausted; rotation
does not establish that additional words exist.

## Running collection continuously

`BASE_URL` in `scripts/crawl_babadum.py` must point at the public game
(`https://babadum.com`). Our own deployment answers `get.php` from the local
library — `server.py` forwards only `category=user` upstream to babadum.com for
auth — so crawling it can only return words already collected. Rounds then
report zero new words indefinitely while looking healthy. Interface caching
(`scripts/cache_interfaces.py`) still targets the deployment, which is correct.

`scripts/proxy_pool.py --refresh --url-file data/proxy/proxy.url` keeps verified
SOCKS5 tunnels over the SSH hosts in `HOSTS` (default `us1`, `reg1`), probing
each port and asking babadum.com for a real round before trusting it. It is the
refresh hook for `scripts/watch_crawler.py` and a fallback when the Colab mint in
`scripts/babadum-proxy-rotate.py` has no connected runtime or no browser on port
9229.

`scripts/supervise_crawler.sh all` wraps the watcher in a restart loop, and
`watch_crawler.py` restarts the crawler child and rotates the proxy when the port
dies or five minutes pass without new words. Both run as launchd agents
(`wtf.babadum.supervisor`, `wtf.babadum.monitor`) so they survive shell sessions
and restart on failure; `launchctl list | grep babadum` shows their state.

`scripts/monitor_library.py` appends totals and working-tree counts to
`data/library/monitor.log` every minute and makes a snapshot commit of
`data/library` once the vocabulary grows by 25 words or 30 minutes pass with
changes pending. It never pushes; pushing to `main` still deploys.
